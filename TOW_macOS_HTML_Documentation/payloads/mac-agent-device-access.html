002 // NINJAONE MDM

Mac Agent Device Access [PPPC]

The TOW Foundation · macOS · Custom MDM Payload

Explanation content is preserved from the current component explanation document. Raw-source tabs use the current available source files.

Payload Purpose

Grants privacy, automation, application-management, and background-service permissions to the primary NinjaOne MacAgent executable located at:

/Applications/NinjaRMMAgent/programfiles/ninjarmm-macagent

This profile is intended to prevent macOS privacy controls from blocking NinjaOne monitoring, scripting, software deployment, patching, automation, and other management functions.

The executable is identified by its full installation path and verified through its NinjaOne code-signing requirement and Team ID EBNT3ZX97E. The profile also approves background components signed by the same Team ID.

How It Functions

Grants the NinjaOne MacAgent access to protected files and user data throughout macOS through SystemPolicyAllFiles = Allow. This supports management tasks that need access to locations protected by Full Disk Access.

Grants access to protected system-administration files through SystemPolicySysAdminFiles = Allow. This explicitly authorizes the agent for protected system-management locations.

Configures Input Monitoring with ListenEvent = AllowStandardUserToSetSystemService. This does not silently enable Input Monitoring; it allows a standard user to approve the permission without administrator credentials if macOS presents the request.

Allows the MacAgent to post synthetic keyboard, mouse, and other input events through PostEvent = Allow. This can support managed workflows that generate user-interface input.

Grants Accessibility access through Accessibility = Allow, allowing the MacAgent to interact with and control elements of the macOS user interface for supported management and automation functions.

Allows access to protected data belonging to other applications through SystemPolicyAppData = Allow. This can support troubleshooting, configuration, and management involving application-owned data.

Allows the MacAgent to update, replace, modify, or remove application bundles through SystemPolicyAppBundles = Allow. This supports managed application deployment, patching, upgrades, and uninstall operations.

Allows the MacAgent to send Apple Events through AppleEvents = Allow specifically to com.apple.systemevents. The receiver is validated as identifier "com.apple.systemevents" and anchor apple, permitting supported AppleScript-style automation of System Events without a separate Automation approval prompt.

Approves managed login items, launch agents, launch daemons, and other background services signed with NinjaOne Team ID EBNT3ZX97E through the com.apple.servicemanagement payload. The rule is Team-ID based, so it applies to qualifying NinjaOne-signed background components rather than only the primary MacAgent executable.

Why This Profile Is Deployed

NinjaOne operates as an RMM and device-management platform and performs actions that extend beyond those of a normal user application.

Without these managed permissions, macOS may prevent or interrupt protected file access, scripting, software deployment, application patching, interface automation, Apple Events, and background services required by the NinjaOne agent.

This profile pre-authorizes the applicable access through MDM so the agent can function consistently without repeatedly depending on manual user approval.

Dependencies And Deployment Notes

The NinjaOne MacAgent must already be installed at:

/Applications/NinjaRMMAgent/programfiles/ninjarmm-macagent

OPERATIONAL WARNING If NinjaOne changes the executable path, signing identifier, Team ID, or code requirement, the applicable PPPC entries must be reviewed and updated or the permissions may no longer match the installed binary.
IMPORTANT CAVEAT ListenEvent is configured as AllowStandardUserToSetSystemService, not Allow. Input Monitoring therefore remains a user-approved permission when macOS requires consent; this profile only removes the administrator-credential requirement for that approval.
IMPORTANT CAVEAT This profile does not grant Screen Recording to NCStreamer, configure Lockhart backup permissions, install the NinjaOne agent, create NinjaOne policies, enable remote access, or define which scripts and automations are permitted to run.

Happy Scripting!
