001 // AUTHENTICATION

Secure Enclave w/ Company Portal V2.3 [PSSO]

The TOW Foundation · macOS · Custom MDM Payload

Explanation content is preserved from the current component explanation document. Raw-source tabs use the current available source files.

Payload Purpose

Configures Microsoft Entra Platform SSO in UserSecureEnclaveKey authentication mode using the Microsoft Company Portal SSO extension.

This profile provides hardware-backed Entra authentication, first-user standard-account provisioning during Setup Assistant, browser and application SSO, and a managed “Other…” sign-in option at the native macOS login window.

Unlike the Password authentication profile, this configuration does not synchronize the user’s Entra password with the local macOS password. Platform SSO instead registers a cryptographic user key protected by the Mac’s Secure Enclave. Password remains permitted as the authentication method used while creating a new local user, but it is not the ongoing Platform SSO authentication method.

The profile contains two managed payloads: an Extensible SSO payload for Microsoft Entra Platform SSO and a Login Window payload that exposes the managed “Other…” sign-in path while preserving normal FileVault auto-login behavior where applicable.

How It Functions

Registers the Mac and user with Microsoft Entra through the Microsoft Company Portal SSO extension using the MDM-supplied {{DEVICEREGISTRATION}} token.

Uses UserSecureEnclaveKey as the Platform SSO AuthenticationMethod. Authentication is based on a device-bound user key protected by the Mac’s Secure Enclave rather than synchronization of the Entra password into the local account.

Enables Platform SSO authorization and permits registration during Setup Assistant through EnableAuthorization and EnableRegistrationDuringSetup.

Enables creation of the first local user during Setup Assistant through EnableCreateFirstUserDuringSetup. NewUserAuthenticationMethods contains Password, while NewUserAuthorizationMode and UserAuthorizationMode are both Standard, so the profile does not grant administrator status to users created or authorized through Platform SSO.

Maps the Entra account short name to the local macOS account name through com.apple.PlatformSSO.AccountShortName and maps the Entra name claim to the local user’s full name.

Excludes the local account named admin from Platform SSO management through NonPlatformSSOAccounts, allowing that account to remain independent of the managed Entra authentication workflow.

Allows device identifiers to be included in Entra attestation through AllowDeviceIdentifiersInAttestation and enables UseSharedDeviceKeys for Platform SSO registration.

Sets ScreenLockedBehavior to DoNotHandle. Platform SSO is therefore not invoked solely because the Mac is at the ordinary locked-screen authentication state; normal local macOS authentication continues to handle screen unlock.

Enables SSO for managed applications, enables browser SSO interaction, and suppresses supported explicit application authorization prompts. AppPrefixAllowList includes com.apple., com.microsoft., com.google., and com.paloaltonetworks.

Uses the Microsoft Company Portal extension com.microsoft.CompanyPortalMac.ssoextension, signed by Microsoft Team ID UBF8T346G9, as a Redirect-type SSO extension.

Redirects supported Microsoft authentication traffic for the explicitly configured Microsoft identity endpoints, including the global, China, and U.S. government sign-in endpoints contained in the payload.

Configures SHOWOTHERUSERS_MANAGED as enabled so the managed “Other…” option is available at the macOS login window. DisableFDEAutoLogin is set to false, meaning this profile does not disable the normal post-FileVault automatic-login behavior.

Why This Profile Is Deployed

This profile provides hardware-backed Microsoft Entra authentication for Macs that use Secure Enclave-based Platform SSO. The user’s cloud password does not become the ongoing Platform SSO credential, reducing reliance on a reusable synchronized password for cloud authentication.

It also supports low-touch initial provisioning by allowing an authorized Entra identity to create the first standard local account during Setup Assistant, while keeping the dedicated local admin account outside Platform SSO management.

The same Microsoft SSO extension provides managed browser and application SSO for supported managed applications and applications covered by the configured Apple, Microsoft, Google, and Palo Alto Networks bundle-identifier prefixes.

Dependencies And Deployment Notes
OPERATIONAL WARNING Microsoft Company Portal must be installed for the configured SSO extension identifier com.microsoft.CompanyPortalMac.ssoextension to exist and for Platform SSO registration to complete.
OPERATIONAL WARNING The MDM platform must replace {{DEVICEREGISTRATION}} with a valid device registration token when delivering the profile.

The Mac must support Secure Enclave-backed Platform SSO authentication and must receive this system-scoped profile through a supported device-management channel.

Users may still need to complete the Microsoft Company Portal registration flow and any Microsoft Entra tenant requirements that apply to their account, such as Conditional Access or multifactor authentication.

IMPORTANT CAVEAT This profile does not synchronize the Entra password with the local macOS password. NewUserAuthenticationMethods = Password permits password-based new-user creation, but the configured Platform SSO AuthenticationMethod remains UserSecureEnclaveKey.
IMPORTANT CAVEAT The current V2.3 payload does not define LoginPolicy, FileVaultPolicy, or EnableCreateUserAtLogin. It therefore should not be documented as explicitly forcing Platform SSO authentication during FileVault unlock or as explicitly enabling additional-user creation from the login window.

IMPLEMENTATION NOTE Earlier Secure Enclave iterations included EnableCreateUserAtLogin, LoginPolicy = AttemptAuthentication, and FileVaultPolicy = AttemptAuthentication during login-window testing. V2.3 intentionally omits them, while the Password-mode PSSO profile retains them. In the current design, Password-mode PSSO handles password synchronization and broader provisioning/login-window behavior, while Secure Enclave PSSO is the steady-state post-enrollment authentication profile.

The profile does not install Microsoft Company Portal, enable FileVault, create the excluded admin account, grant administrator rights to Entra users, or independently configure Conditional Access or multifactor-authentication requirements.

AppPrefixAllowList currently contains com.apple., com.microsoft., com.google., and com.paloaltonetworks; update the profile if additional application identifier prefixes require managed SSO. The redirect URL list is also explicitly defined, so the payload should be reviewed if Microsoft changes the identity endpoints required by Company Portal or the Enterprise SSO extension.
