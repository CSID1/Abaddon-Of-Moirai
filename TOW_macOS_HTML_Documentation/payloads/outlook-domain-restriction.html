Outlook Domain Restriction

The TOW Foundation · macOS · Custom MDM Payload

Explanation content is preserved from the current component explanation document. Raw-source tabs use the current available source files.

Payload Purpose

Restricts account additions in Microsoft Outlook for Mac to the approved corporate email domain towfoundation.org.

The profile contains one com.apple.ManagedClient.preferences payload that writes a forced managed preference to the com.microsoft.Outlook preference domain. The configured Outlook key is AllowedEmailDomains.

Its purpose is to keep newly added Outlook mailboxes within the organization's approved domain without changing unrelated Outlook settings.

How It Functions

Delivers the Outlook mailbox restriction through the managed preference domain com.microsoft.Outlook.

Sets AllowedEmailDomains to an array containing one approved value: towfoundation.org. Outlook uses this allowlist when determining which email domains users are permitted to add as mailboxes.

Places the setting inside the Forced managed-preference collection. While the profile is applied, the organization supplies the effective value rather than relying on an unmanaged per-user preference.

Restricts new mailbox additions; it does not retroactively remove or disconnect a mailbox that was already present in Outlook before the restriction was applied.

Uses an allowlist rather than a denylist. The payload does not configure DisallowedEmailDomains; the only domain explicitly permitted by this profile is towfoundation.org.

Does not automatically add or prepopulate a mailbox. The profile does not configure DefaultEmailAddressOrDomain or OfficeAutoSignIn, so mailbox provisioning and Office sign-in remain separate workflows.

Uses payload display name Microsoft Outlook - Allowed Email Domains and profile display name Microsoft Outlook - Corporate Accounts Only under organization The TOW Foundation.

The current profile sets PayloadRemovalDisallowed = false, so the configuration itself is not marked as non-removable. The top-level profile does not explicitly define a PayloadScope key.

Why This Profile Is Deployed

This profile keeps Microsoft Outlook aligned with the organization's corporate-account model by preventing users from adding new mailboxes from domains outside towfoundation.org.

It reduces accidental use of personal or unrelated external mailboxes inside the managed Outlook application while leaving the rest of the Outlook configuration independently manageable.

Keeping this restriction in a small dedicated payload also makes the approved domain list easy to identify and update without mixing it with unrelated Outlook preferences.

Dependencies And Deployment Notes
OPERATIONAL WARNING The current allowlist contains only towfoundation.org. If the organization introduces another accepted email domain, alias domain, or separate corporate namespace that users must add to Outlook, that domain must be added to AllowedEmailDomains before those mailboxes can be added.
IMPORTANT CAVEAT Microsoft documents that AllowedEmailDomains does not remove or disconnect accounts that were already added to Outlook. Existing non-approved mailboxes therefore require a separate remediation process if they need to be removed.
IMPORTANT CAVEAT This profile is an Outlook account-admission restriction, not a data-loss-prevention policy. It does not block message forwarding, exporting, copying data elsewhere, or use of another mail client or webmail service.

Microsoft Outlook must be installed for the com.microsoft.Outlook managed preference to have an application that can consume it. This profile does not install Outlook or sign the user into Microsoft 365.

The payload does not configure HideCanAddOtherAccountTypesTipText, so it does not independently hide Outlook interface text that may mention adding other account types.

The profile does not configure ItemsToOtherAccountsEnabled or any other cross-account message-movement control. Those behaviors, if required, should be managed separately.
