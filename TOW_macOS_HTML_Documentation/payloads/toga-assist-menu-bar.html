TOGA Assist Menu Bar Item

The TOW Foundation · macOS · Custom MDM Payload

Explanation content is preserved from the current component explanation document. Raw-source tabs use the current available source files.

Payload Purpose

Configures the NinjaOne NJBar menu bar application so it launches automatically when a user signs in, is permitted to run with its supporting background services, and can display managed macOS notifications.

The profile contains three managed payloads: com.apple.notificationsettings for NJBar notifications, com.apple.servicemanagement for NinjaOne-signed background services, and com.apple.loginitems.managed to launch NJBar at user login.

How It Functions

Enables managed notifications for bundle identifier org.njbar.daemon. The payload permits notifications to appear as temporary banners, in Notification Center, and on the Lock Screen, and also permits notification sounds and application badges.

Sets AlertType = 1. In this notification payload, that configures temporary banner-style alerts rather than persistent alerts.

Approves and enables background services signed by the NinjaOne developer Team ID EBNT3ZX97E through a TeamIdentifier Service Management rule. The rule is broader than NJBar itself and can match NinjaOne login items, launch agents, launch daemons, and related signed background components.

Launches NJBar automatically whenever a user logs in by adding the managed login item /Applications/NinjaRMMAgent/programfiles/njbar.app.

Sets Hide = false, so macOS is not instructed to launch NJBar in a hidden state. Because NJBar is a menu bar application, its normal visible interface is expected to appear in the menu bar rather than as a standard application window.

Applies the configuration at PayloadScope = System under the top-level organization value Agilant.

Why This Profile Is Deployed

NJBar needs to remain available after user login so users can access NinjaOne-provided support functions, device information, and organization-provided automations without manually locating or opening the application.

The managed background-service rule reduces the chance that required NinjaOne components are disabled through macOS background-item controls, while the notification payload allows NJBar to present support notices, status messages, automation results, and other NinjaOne-generated information to the signed-in user.

Dependencies And Deployment Notes
OPERATIONAL WARNING The NinjaOne MacAgent and NJBar application must already be installed, and NJBar is expected at /Applications/NinjaRMMAgent/programfiles/njbar.app. This profile does not install NJBar or the NinjaOne agent.
OPERATIONAL WARNING The configuration depends on the current NJBar bundle identifier org.njbar.daemon, application path /Applications/NinjaRMMAgent/programfiles/njbar.app, and NinjaOne Team ID EBNT3ZX97E. If NinjaOne changes any of these identifiers, the affected payload entry must be reviewed and updated.
IMPORTANT CAVEAT The TeamIdentifier = EBNT3ZX97E background-service rule is intentionally broad. It can allow matching background components signed by the same NinjaOne developer team and is not limited only to NJBar.
IMPORTANT CAVEAT The separate NinjaOne MacAgent Device Access profile also contains a Service Management TeamIdentifier rule for EBNT3ZX97E. When both profiles are assigned to the same Mac, that portion is functionally redundant, although keeping it in both profiles can preserve independent policy assignment and profile portability.
IMPORTANT CAVEAT This profile does not grant Accessibility, Full Disk Access, Input Monitoring, Screen Recording, Apple Events automation, or other PPPC permissions. Those permissions are handled separately by the relevant NinjaOne device-access profiles.

The payload can launch NJBar and permit its notifications/background services, but it cannot guarantee that the menu bar item remains visible if the application is missing, crashes, is incompatible with the installed macOS version, or is otherwise prevented from running.
