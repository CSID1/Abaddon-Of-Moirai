001 // AUTHENTICATION

Password Synchronization w/ Company Portal V2.1 [PSSO]

The TOW Foundation · macOS · Custom MDM Payload

Explanation content is preserved from the current component explanation document. Raw-source tabs use the current available source files.

Payload Purpose

Configures Microsoft Entra Platform SSO in Password authentication mode using the Microsoft Company Portal SSO extension.

This profile is intended to provide Entra authentication, synchronization between the user's Entra password and corresponding local macOS password, automatic standard-user account creation, browser and application SSO, and an Entra sign-in option at the native macOS login window.

The profile contains two managed payloads: an Extensible SSO payload for Microsoft Entra Platform SSO and a Login Window payload that keeps the normal macOS user list available while exposing the managed “Other…” sign-in path.

How It Functions

Registers the Mac with Microsoft Entra through the Microsoft Company Portal SSO extension using the MDM-supplied {{DEVICEREGISTRATION}} token.

Uses Password as the Platform SSO authentication method. The same Password method is also specified for newly created users, establishing password-based Platform SSO rather than Secure Enclave key authentication.

Allows Platform SSO registration during Setup Assistant and enables authorization through the Platform SSO framework.

Allows the first local user to be created during Setup Assistant and allows additional users to be created from the macOS login window. Both NewUserAuthorizationMode and UserAuthorizationMode are set to Standard, so Platform SSO-created or authorized users are not granted administrator status by this profile.

Maps the Entra account short name to the local macOS account name through com.apple.PlatformSSO.AccountShortName and maps the Entra name claim to the local user's full name.

Uses shared device keys for Platform SSO registration and allows device identifiers to be included in Entra attestation.

Configures both LoginPolicy and FileVaultPolicy with AttemptAuthentication. This instructs macOS to attempt Platform SSO authentication at the login window and during supported FileVault authentication flows when the required identity and network services are available.

Sets ScreenLockedBehavior to DoNotHandle. Platform SSO is therefore not invoked solely because the Mac is at the normal locked-screen authentication state; local macOS authentication continues to handle ordinary screen unlock.

Excludes the local account named admin from Platform SSO management through NonPlatformSSOAccounts so that account remains outside the managed Entra sign-in and synchronization workflow.

Enables SSO for managed applications and permits SSO interaction for applications whose bundle identifiers begin with com.apple., com.microsoft., or com.google.

Enables browser SSO interaction and suppresses supported explicit application authorization prompts through the Microsoft Enterprise SSO extension.

Uses Microsoft Company Portal extension com.microsoft.CompanyPortalMac.ssoextension, signed by Microsoft Team ID UBF8T346G9, as a Redirect-type SSO extension.

Redirects supported Microsoft authentication traffic for the configured Microsoft identity endpoints, including login.microsoftonline.com, login.microsoft.com, sts.windows.net, the Microsoft China identity endpoints, and the Microsoft U.S. government identity endpoints.

Configures the macOS login window with SHOWFULLNAME disabled and SHOWOTHERUSERS_MANAGED enabled. This preserves the normal user-list style login window while making the managed “Other…” sign-in option available for entering an Entra identity.

Why This Profile Is Deployed

This profile provides a unified Entra and local macOS credential experience for users whose accounts are managed through Microsoft Platform SSO. Password-mode Platform SSO allows the cloud identity and local account password workflow to remain synchronized instead of requiring a permanently separate unmanaged local credential.

It also supports low-touch account provisioning by permitting authorized Entra identities to create standard local accounts during Setup Assistant or from the macOS login window, while keeping the dedicated local admin account outside Platform SSO management.

The same Microsoft SSO extension is also used to provide managed browser and application SSO for supported Microsoft, Apple, Google, and other managed applications covered by the profile.

Dependencies And Deployment Notes

Microsoft Company Portal must be installed for the configured SSO extension identifier com.microsoft.CompanyPortalMac.ssoextension to exist and for Platform SSO registration to complete.

The MDM platform must replace {{DEVICEREGISTRATION}} with a valid device registration token when delivering the profile.

The Mac must receive the profile through a supported device-management channel. The profile is system-scoped and contains both com.apple.extensiblesso and com.apple.loginwindow payloads.

Platform SSO authentication attempts at the login window or during supported FileVault authentication depend on the required network and Microsoft identity services being reachable.

The profile explicitly excludes the local account named admin, but it does not create that account or manage its password.

This profile does not install Microsoft Company Portal, enable FileVault, grant administrator rights to Entra users, or independently configure Conditional Access or multifactor-authentication requirements.

The AppPrefixAllowList currently contains only com.apple., com.microsoft., and com.google. If SSO is later required for additional application identifier prefixes, the profile must be updated accordingly.

The redirect URL list is explicitly defined in the profile. If Microsoft changes the identity endpoints required by Company Portal or the Enterprise SSO extension, the payload should be reviewed before those changes are adopted.
