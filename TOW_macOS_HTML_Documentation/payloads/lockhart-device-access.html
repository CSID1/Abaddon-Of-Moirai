002 // NINJAONE MDM

Lockhart Device Access [PPPC]

The TOW Foundation · macOS · Custom MDM Payload

Explanation content is preserved from the current component explanation document. Raw-source tabs use the current available source files.

Payload Purpose

Grants privacy permissions to the NinjaOne Lockhart backup executable located at:

/Applications/NinjaRMMAgent/programfiles/lockhart/bin/lockhart

This profile is intended to prevent macOS privacy controls from blocking the Lockhart component while it discovers, reads, and processes files for NinjaOne backup operations.

The permissions are assigned to the executable by its full path and verified using its NinjaOne code-signing requirement and Team ID EBNT3ZX97E. This helps prevent an unrelated or replacement binary at the same path from inheriting the permissions.

How It Functions

Grants Lockhart access to protected files throughout macOS, including protected user data and system-administration files. This is intended to allow the backup component to read files that would otherwise be inaccessible because of macOS privacy protections. Apple identifies SystemPolicyAllFiles as access to all protected files, including system-administration files.

Allows Lockhart to access data belonging to other applications. This permission is separate from general Full Disk Access and applies to protected application-owned data on macOS 14 and later. It may help Lockhart include application data in backup operations when that data is protected by macOS.

Grants Lockhart permission to interact with or control elements of the macOS user interface. This may support backup operations that require interaction with system or application processes. It should not be interpreted as Screen Recording, Input Monitoring, or remote-control permission.

Allows Lockhart to detect when the user is interacting with files managed through an Apple File Provider. This may help the backup component recognize activity involving files stored by services that use Apple’s File Provider framework. It does not independently download cloud-only files or grant access to every cloud-storage provider.

Every permission is limited to the binary at the configured path whose signature matches: identifier lockhart and whose signing certificate contains NinjaOne Team ID: EBNT3ZX97E The permissions therefore depend on both the expected installation path and the expected NinjaOne signature.

Why This Profile Is Deployed

macOS protects user files, application data, system files, and certain file-provider activity behind its Transparency, Consent, and Control privacy system.

Without the required managed permissions, the Lockhart backup process may be unable to read some protected files or application data, potentially resulting in incomplete backups, permission errors, or skipped content.

This profile pre-authorizes the relevant access through MDM so the backup component does not need to depend on users manually approving privacy prompts.

Dependencies And Deployment Notes

The NinjaOne agent and Lockhart backup component must already be installed at the configured path.

OPERATIONAL WARNING If NinjaOne changes Lockhart’s installation path, executable identifier, Team ID, or signing requirement in a future release, this profile may need to be updated.

SystemPolicyAppData applies only to macOS 14 and later. Older supported versions of macOS will not use that particular service entry.

FileProviderPresence only allows awareness of user activity involving File Provider-managed files. It does not guarantee that cloud-only or placeholder files are downloaded and available for backup.

IMPORTANT CAVEAT This profile does not install Lockhart, enable a NinjaOne backup plan, select backup locations, define retention rules, configure encryption, or verify that backups complete successfully.
