Overview

Description

This configuration manages FileVault full-disk encryption on managed macOS devices.

FileVault encryption is required across all three macOS policies. Devices are configured to enable FileVault during Setup Assistant for new enrollments or during login when applicable, and the resulting personal recovery key is escrowed to NinjaOne for administrative recovery purposes.

Escrow recovery key

000 Master Status
Enabled
001 Pre-Enrollment Status
Enabled
002 Post-Enrollment Status
Enabled

Requires the FileVault personal recovery key generated for each encrypted Mac to be reported to and stored by NinjaOne.

The escrowed recovery key can be retrieved from the applicable device's details within NinjaOne for administrative recovery purposes.

If recovery-key escrow were later disabled, devices that previously reported their key would no longer continue reporting future recovery-key changes. If the key changed afterward, NinjaOne would not receive the new value unless the device were re-enrolled or otherwise caused to escrow the new key again.

Number of allowed deferrals

000 Master Status

001 Pre-Enrollment Status

002 Post-Enrollment Status
0

Defines how many times a user may postpone the FileVault enablement prompt.

A value of 0 means no deferrals are permitted. When FileVault enablement is required and has not already occurred during Setup Assistant, the user is prompted to enable FileVault at the next applicable login.

NinjaOne also supports a value of -1 for unlimited deferrals, but that behavior is not configured here.

Prevents the FileVault enablement prompt from appearing during user logout.

If FileVault still needs to be enabled, the user is prompted during login rather than during logout.

Effective Filevault Behavior

FileVault encryption is mandatory on managed macOS devices.

New enrollments are configured to enable FileVault during Setup Assistant.

If encryption still requires user interaction after enrollment, no user deferrals are permitted.

FileVault prompts are presented at login rather than logout.

The personal recovery key is automatically escrowed to NinjaOne.

The personal recovery key is not displayed to the end user after encryption.
