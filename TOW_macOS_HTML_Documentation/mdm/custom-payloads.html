Overview

Description

This configuration contains custom MDM payloads that are deployed directly through the NinjaOne macOS policy.

All custom payloads listed below are enabled at the 000 Master MacOS Policy level.

Some payloads are intentionally overridden and disabled within the 001 Pre-Enrollment Policy or 002 Post-Enrollment Policy depending on when the configuration should become active during the device enrollment lifecycle.

The specific effective status of each payload is therefore documented individually below.

Each payload will also include or reference

  • The raw custom payload file
  • A detailed explanation document describing the payload's purpose, configuration, behavior, dependencies, and implementation logic

These supporting files serve as the detailed technical documentation for each payload, while this section documents policy-level inclusion and lifecycle status.

Custom Payload Lifecycle Behavior

All 15 custom payloads are enabled at the 000 Master MacOS Policy level.

The 001 Pre-Enrollment Policy and 002 Post-Enrollment Policy may override individual payloads and disable them where their configuration should not apply during that stage of the device lifecycle.

A payload marked Disabled within 001 or 002 should be interpreted as an intentional policy override rather than removal from the overall macOS configuration architecture.

The raw payload and explanation document associated with each entry contain the authoritative technical details of that payload.

This section primarily documents:

1. Which custom payloads exist

2. Whether each payload is active within each policy

3. Where the detailed payload documentation is located

Configuration Ownership: This documentation describes the current implementation and does not constitute authorization to modify it. Configuration changes should be coordinated with the endpoint-management owner and reflected in the corresponding source configuration.

Source hierarchy: raw NinjaOne configuration / raw script or mobileconfig → component explanation documentation → architecture and policy documentation.
