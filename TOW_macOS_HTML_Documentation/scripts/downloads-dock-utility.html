Downloads Folder Insertion / Dock Utility

The TOW Foundation · macOS · NinjaOne ShellScript

Explanation content is preserved from the current script explanation document. Raw-source tabs use the current available source files.

Script Purpose

Adds each user's Downloads folder to the document/folder side of the macOS Dock using dockutil. The script is intended to restore or standardize the Downloads stack without modifying the managed application-side Dock items.

The script consists of a single /usr/local/bin/dockutil command and applies the change across user home directories through --allhomes.

How It Functions

Calls the dockutil binary from the exact path /usr/local/bin/dockutil. The script therefore depends on DockUtil already being installed at that location.

Adds the Dock item specified as ~/Downloads. The path is passed to DockUtil as a literal argument because it is enclosed in single quotes; DockUtil is responsible for interpreting that user-relative path when processing the target home directories.

Uses --section others so the Downloads item is placed on the document/folder side of the Dock rather than among application icons.

Uses --view grid so selecting the Downloads stack opens its contents using the Dock's grid presentation.

Uses --display folder so the Dock item is visually represented as a folder instead of using a content-based stack appearance.

Uses --allhomes so DockUtil applies the requested Dock change across local user home directories rather than only the account under which the script is executed.

Why This Script Is Deployed

This script complements the managed Dock configuration by restoring a standardized Downloads folder stack after enrollment or Dock cleanup operations.

Keeping the folder insertion separate from the static application payload allows the managed application layout to remain focused on application entries while the user-facing Downloads stack is added operationally through DockUtil.

It also pairs naturally with the separate Clear Non-Forced Apps From Dock workflow: that script can remove existing user-persistent application entries, while this script explicitly re-adds the Downloads folder on the non-application side of the Dock.

Dependencies And Deployment Notes

OPERATIONAL DEPENDENCY DockUtil must already exist at /usr/local/bin/dockutil. If the binary is missing, installed elsewhere, or renamed, this script will fail immediately because it does not search for an alternate location.

OPERATIONAL NOTE The script does not explicitly remove an existing Downloads entry before attempting to add one. Resulting duplicate-handling behavior is therefore determined by the installed DockUtil version and the target user's existing Dock state.
IMPORTANT CAVEAT The script passes ~/Downloads in single quotes. The shell itself does not expand the tilde. The workflow therefore relies on DockUtil correctly resolving the user-relative path while processing --allhomes.

This script does not create the Downloads folder, install DockUtil, restart the Dock process explicitly, or define the application-side managed Dock layout. Those responsibilities are handled separately.

Happy Scripting!

Raw ZSH
Downloads_Folder_Insertion_Dock-Utility.zsh
ZSH
#!/bin/zsh

/usr/local/bin/dockutil --add '~/Downloads' \
  --section others \
  --view grid \
  --display folder \
  --allhomes
