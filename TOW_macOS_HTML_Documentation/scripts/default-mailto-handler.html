Set Default mailto: Handler to Outlook

The TOW Foundation · macOS · NinjaOne ShellScript

Explanation content is preserved from the current script explanation document. Raw-source tabs use the current available source files.

Script Purpose

Sets Microsoft Outlook as the signed-in user's default application for mailto: URL links on macOS.

This controls what application opens when a browser, document, contact record, or other application launches a link such as mailto:user@example.com. It is separate from the .eml file-association workflow, which controls which application opens saved email-message files.

How It Functions

Runs under #!/bin/bash and defines a restricted executable PATH=/usr/bin:/bin:/usr/sbin:/sbin.

Defines /Applications/Microsoft Outlook.app as the target application and com.microsoft.Outlook as the expected Launch Services bundle identifier.

Determines the active console user with stat -f "%Su" /dev/console. An empty value, root, or loginwindow is treated as no valid interactive user and causes an exit with status 1.

Resolves the signed-in user's numeric UID with id -u and verifies that Outlook exists at /Applications/Microsoft Outlook.app before attempting any handler change.

Defines run_as_console_user() using launchctl asuser and sudo -H -u so Launch Services operations execute inside the signed-in user's graphical session rather than only in the management process context.

Queries the current mailto: handler through an inline AppleScriptObjC block using NSWorkspace's URLForApplicationToOpenURL method and the test URL mailto:test@example.invalid.

Returns the current application's bundle identifier when available. If Launch Services cannot provide a normal bundle object, the query falls back to the resolved application path; if no handler exists, it returns NONE.

If the current handler already equals com.microsoft.Outlook, the script logs that Outlook is already the default mailto: handler and exits successfully without building a helper application.

If Outlook is not already the handler, creates a private temporary working directory under /private/tmp/default-mail.XXXXXX and registers an EXIT trap that removes the directory when the script ends.

Generates an AppleScriptObjC helper that activates as a regular GUI application, resolves /Applications/Microsoft Outlook.app to an NSURL, and calls setDefaultApplicationAtURL:toOpenURLsWithScheme:completionHandler: for the mailto scheme.

Keeps the helper's Cocoa run loop alive for 45 seconds after submitting the asynchronous request so macOS has time to process the Launch Services handler change.

Compiles the helper into Default Mail Setup.app using osacompile. If compilation fails or the resulting app bundle does not exist, the script exits with status 1.

Changes ownership of the temporary directory to the signed-in user and applies u+rwX,go+rX permissions so the helper can run normally in that user's session.

Launches the temporary helper with open -W -n. The -W option waits for the helper to finish, while -n requests a new application instance.

In the current environment, changing the mailto: link handler to Outlook does not present the same native two-button confirmation prompt seen with file associations such as .eml or .pdf. The change is processed as a URL-handler assignment.

After the helper finishes, queries the mailto: handler again and verifies the result rather than assuming the API request succeeded.

Returns exit 0 only when the verified handler equals com.microsoft.Outlook. If the handler remains unchanged, the script logs that no Launch Services preference files were directly modified and exits with status 2.

Why This Script Is Deployed

The script standardizes compose-link behavior so clicking an email link launches Microsoft Outlook rather than Apple Mail or another registered mail application.

Running the request in the interactive user's Launch Services context is important because default URL handlers are user-specific behavior. The final verification confirms the setting that the signed-in user will actually receive.

The script uses Apple's NSWorkspace API rather than directly editing Launch Services preference files or databases.

Relationship To .Eml File Handling

IMPORTANT DISTINCTION This script manages the mailto: URL scheme only. It does not determine which application opens a saved .eml file.

Tow therefore manages the two behaviors separately: the .eml workflow controls saved-message files and can trigger a native macOS confirmation prompt; this mailto: workflow controls email links and, in observed use, applies without that file-opener confirmation.

Dependencies And Deployment Notes
OPERATIONAL WARNING Outlook must already exist at the exact path /Applications/Microsoft Outlook.app. The script does not install Outlook or search alternate application locations.
OPERATIONAL NOTE The script hard-codes the expected bundle identifier as com.microsoft.Outlook rather than reading CFBundleIdentifier from Outlook's Info.plist. A future Microsoft packaging change that alters the bundle identifier would require the script to be updated.

OBSERVED BEHAVIOR NOTE The helper source and log text were written defensively to allow for the possibility that macOS could display a confirmation request, and the helper is kept alive for 45 seconds. In the current Tow environment, however, mailto: handler changes have not displayed that confirmation prompt.

IMPORTANT CAVEAT The helper waits a fixed 45 seconds and does not poll for early success. Even when Launch Services applies the handler almost immediately, open -W waits for the helper to finish its full run-loop period before the shell performs final verification.
OPERATIONAL NOTE The helper uses NSApplicationActivationPolicyRegular and activates itself. It is not marked LSUIElement like the Zoom link-handler helper, so the temporary helper can briefly behave as a normal GUI application while it runs.
IMPORTANT CAVEAT The script is designed for privileged management execution but contains no explicit EUID/root check. If launched outside the normal root-based NinjaOne workflow, the sudo -u, ownership, or helper-management operations may fail.

The test address test@example.invalid uses the reserved .invalid domain only to construct a sample URL for handler discovery. No email is sent.

The script does not configure Outlook account setup, Exchange connectivity, notifications, .eml handling, browser SSO, or any Outlook preference beyond the mailto: Launch Services handler.

Happy Scripting!

Raw ZSH
Set_Default_Mailto_Handler_to_Outlook.zsh
ZSH
#!/bin/bash

PATH="/usr/bin:/bin:/usr/sbin:/sbin"

TARGET_APP="/Applications/Microsoft Outlook.app"
TARGET_BUNDLE_ID="com.microsoft.Outlook"

log() {
    echo "[DefaultMail] $*"
}

console_user=$(/usr/bin/stat -f "%Su" /dev/console)

if [[ -z "$console_user" || "$console_user" == "root" || "$console_user" == "loginwindow" ]]; then
    log "No signed-in user was detected."
    exit 1
fi

console_uid=$(/usr/bin/id -u "$console_user")

if [[ ! -d "$TARGET_APP" ]]; then
    log "Outlook was not found at: $TARGET_APP"
    exit 1
fi

run_as_console_user() {
    /bin/launchctl asuser "$console_uid" \
        /usr/bin/sudo -H -u "$console_user" "$@"
}

get_mailto_handler() {
    run_as_console_user /usr/bin/osascript <<'APPLESCRIPT'
use framework "AppKit"
use framework "Foundation"

set workspace to current application's NSWorkspace's sharedWorkspace()
set mailtoURL to current application's NSURL's URLWithString:"mailto:test@example.invalid"
set applicationURL to workspace's URLForApplicationToOpenURL:mailtoURL

if applicationURL is missing value then
    return "NONE"
end if

set applicationBundle to current application's NSBundle's bundleWithURL:applicationURL

if applicationBundle is missing value then
    return applicationURL's |path|() as text
end if

set bundleIdentifier to applicationBundle's bundleIdentifier()

if bundleIdentifier is missing value then
    return applicationURL's |path|() as text
end if

return bundleIdentifier as text
APPLESCRIPT
}

current_handler=$(get_mailto_handler)

log "Signed-in user: $console_user"
log "Current mailto handler: $current_handler"

if [[ "$current_handler" == "$TARGET_BUNDLE_ID" ]]; then
    log "Outlook is already the default mailto handler."
    exit 0
fi

temporary_directory=$(/usr/bin/mktemp -d "/private/tmp/default-mail.XXXXXX")
applet_source="$temporary_directory/main.applescript"
applet_path="$temporary_directory/Default Mail Setup.app"

cleanup() {
    if [[ -n "$temporary_directory" && -d "$temporary_directory" ]]; then
        /bin/rm -rf "$temporary_directory"
    fi
}

trap cleanup EXIT

/bin/cat > "$applet_source" <<'APPLESCRIPT'
use framework "AppKit"
use framework "Foundation"
use scripting additions

on run
    set applicationObject to current application's NSApplication's sharedApplication()

    applicationObject's setActivationPolicy:(current application's NSApplicationActivationPolicyRegular)
    applicationObject's activateIgnoringOtherApps:true

    set workspace to current application's NSWorkspace's sharedWorkspace()
    set outlookURL to current application's NSURL's fileURLWithPath:"/Applications/Microsoft Outlook.app"

    workspace's setDefaultApplicationAtURL:outlookURL ¬
        toOpenURLsWithScheme:"mailto" ¬
        completionHandler:(missing value)

    -- Keep this GUI process and its Cocoa event loop alive so macOS can
    -- display and process the default-application consent request.
    set expirationDate to current application's NSDate's dateWithTimeIntervalSinceNow:45
    current application's NSRunLoop's currentRunLoop()'s runUntilDate:expirationDate
end run
APPLESCRIPT

log "Building temporary user-facing NSWorkspace helper."

/usr/bin/osacompile -o "$applet_path" "$applet_source"

compile_status=$?

if [[ "$compile_status" -ne 0 || ! -d "$applet_path" ]]; then
    log "Unable to build the temporary helper."
    exit 1
fi

/usr/sbin/chown -R "$console_uid" "$temporary_directory"
/bin/chmod -R u+rwX,go+rX "$temporary_directory"

log "Launching the NSWorkspace helper for $console_user."
log "A macOS confirmation window may now appear."

run_as_console_user /usr/bin/open -W -n "$applet_path"

launch_status=$?

if [[ "$launch_status" -ne 0 ]]; then
    log "The temporary helper returned exit code $launch_status."
fi

current_handler=$(get_mailto_handler)

log "Mailto handler after the request: $current_handler"

if [[ "$current_handler" == "$TARGET_BUNDLE_ID" ]]; then
    log "Success: Outlook is now the default mailto handler."
    exit 0
fi

log "The NSWorkspace request completed without changing the handler."
log "No Launch Services preference files were modified."
exit 2
