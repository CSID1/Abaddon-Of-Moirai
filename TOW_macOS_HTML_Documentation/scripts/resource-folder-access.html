Resource Folder Access

The TOW Foundation · macOS · NinjaOne ShellScript

Explanation content is preserved from the current script explanation document. Raw-source tabs use the current available source files.

Script Purpose

Ensures files stored in the shared /Users/Shared/Tow Foundation resource folder remain readable and traversable by local users even when new files are transferred to the Mac by NinjaOne under the root account.

The script does not change ownership of the transferred files. Instead, it broadens their POSIX permissions and applies an inherited ACL so a non-root user can open resources placed in this shared directory.

How It Functions

Runs chmod -R 755 "/Users/Shared/Tow Foundation". This recursively sets the owner permissions to read/write/execute and the group/other permissions to read/execute throughout the shared resource tree.

Because 755 is applied recursively, directories become traversable by all users and files become readable by all users. The numeric mode does not change file ownership, so files originally created by root remain root-owned.

Runs a second recursive chmod command that adds the ACL entry everyone allow read,execute,file_inherit,directory_inherit to the same shared folder tree.

The ACL explicitly grants everyone read and execute/traverse access and includes file_inherit and directory_inherit flags so newly created descendants can inherit the access rule from their parent directories.

Both commands are prefixed with sudo. In the current deployment model the script itself normally runs as root through NinjaOne, so the explicit sudo is functionally redundant but does not change the intended result.

Why This Script Is Deployed

This script exists primarily because NinjaOne File Transfer runs under the root context. Files copied into /Users/Shared/Tow Foundation can therefore arrive owned by root with permissions that prevent the interactive user from opening them.

In observed use, simply being a standard local administrator has not been sufficient to guarantee access to those root-owned resources. Administrator group membership does not automatically bypass normal file-system mode bits and ACL decisions for ordinary file access.

The script is therefore run semi-frequently as a maintenance/remediation action after new shared resources may have been delivered. Its practical purpose is to make those files usable without requiring the user to become root or manually repair permissions.

Examples of resources stored in this location include wallpapers, prompt images, notification assets, and other files used by Tow Foundation onboarding or automation workflows.

Relationship To Ninjaone File Transfer

NinjaOne File Transfer is responsible for placing the resource on disk; this script is responsible for normalizing access afterward. The two actions are intentionally separate.

A successful transfer therefore does not necessarily mean the signed-in user can immediately open the file. If the transferred object's inherited or created permissions are too restrictive, this script repairs access across the shared resource tree.

OPERATIONAL NOTE The inherited ACL is intended to reduce the need for future repairs, but the script is still run periodically because newly transferred files may not always arrive with the expected effective access in the live NinjaOne workflow.
Dependencies And Deployment Notes
IMPORTANT CAVEAT The script grants access by modifying permissions, not ownership. A transferred file can remain owned by root while still becoming readable by standard users after this script runs.
IMPORTANT CAVEAT Using chmod -R 755 applies the execute bit to regular files as well as directories. This is broader than the minimum permission required merely to read ordinary images, documents, or other static resources. A narrower implementation could use different modes for files and directories if that distinction becomes operationally important.
SECURITY NOTE The ACL applies to everyone, not only the intended signed-in user or local administrators. Any local account that can reach this folder can receive the granted read/execute access.
OPERATIONAL NOTE The script contains no explicit folder-existence check, logging, or custom error handling. It also does not use set -e. Command failures are therefore reported only through the shell/chmod output and the eventual command exit status.

The target path /Users/Shared/Tow Foundation is hard-coded. If the shared-resource location changes, both recursive permission commands must be updated.

Happy Scripting!

Raw ZSH
Resource_Folder_Access.zsh
ZSH
sudo chmod -R 755 "/Users/Shared/Tow Foundation"
sudo chmod -R +a "everyone allow read,execute,file_inherit,directory_inherit" \
"/Users/Shared/Tow Foundation"
