macOS Standard User Printer Control

The TOW Foundation · macOS · NinjaOne ShellScript

Explanation content is preserved from the current script explanation document. Raw-source tabs use the current available source files.

Script Purpose

Allows standard macOS users to perform printer add/remove operations governed by the local authorization right system.preferences.printing without administrator authentication.

The script is intended for root execution through NinjaOne. Before changing the Authorization Database, it creates a one-time backup of the existing authorization rule for rollback or forensic comparison.

How It Functions

Defines the target authorization right as system.preferences.printing. This is the only Authorization Database right the script intentionally modifies.

Defines a protected backup location at /Library/Application Support/Agilant/AuthorizationDB Backups/system.preferences.printing.plist.

Requires root execution by checking id -u. A non-root run prints an error and exits with status 1.

Creates /Library/Application Support/Agilant/AuthorizationDB Backups if it does not already exist and applies mode 700 to the directory.

Backs up the current authorization rule only when no non-empty backup file already exists. The existing rule is read with security authorizationdb read system.preferences.printing and written to the backup plist.

Validates the backup with plutil -lint. An unreadable or invalid backup is deleted and the script exits rather than modifying the live authorization rule.

Applies mode 600 to the successful backup and intentionally leaves any later existing backup untouched so the original captured rule is not overwritten.

Changes the live authorization rule with security authorizationdb write system.preferences.printing allow. This replaces the right's current policy with the literal authorization result allow.

Verifies the live rule by reading it back and requiring the output to contain <string>allow</string>. Verification success exits with status 0; failure exits with status 1.

Why This Script Is Deployed

This script provides a direct local fallback for environments where standard users need to add or remove printers without administrator credentials and a managed printing configuration alone is not producing the required behavior.

Unlike a normal configuration profile, this script modifies the Mac's local Authorization Database directly. That makes it useful as a compatibility or remediation mechanism, but also makes it a broader and more persistent change.

Relationship To User Printer Access Payload

Tow's existing User Printer Access configuration profile already sets the managed Printing payload so users can modify printers without an administrator requirement, including RequireAdminToAddPrinters = false, RequireAdminToPrintLocally = false, AllowLocalPrinters = true, and ShowOnlyManagedPrinters = false.

Preferred design: use the managed Printing payload by itself when it successfully provides the required standard-user printer workflow. It is declarative, visible in MDM, removable, and easier to audit than an Authorization Database rewrite.

FALLBACK USE CASE Keep or deploy this script only if testing shows that a standard user still receives an administrator prompt for an add/remove operation that is controlled by system.preferences.printing despite the managed Printing payload.

IMPORTANT DIFFERENCE The two methods are not exact duplicates internally. The payload configures Apple's managed printing policy; this script forcibly rewrites the local authorization right to allow. Running both can make the script appear necessary even when the profile would have been sufficient, because the Authorization Database change can mask the profile's actual behavior.

Dependencies And Deployment Notes
IMPORTANT CAVEAT This script makes a persistent local Authorization Database change. Removing the MDM Printing profile later does not automatically restore the original system.preferences.printing rule.

ROLLBACK NOTE The script creates a one-time backup of the original right, but it does not contain rollback logic. Restoring the prior rule requires a separate administrative action that writes the saved plist back to system.preferences.printing.

SECURITY NOTE Writing the authorization right as the literal rule allow is broader than simply expressing a managed preference. Any local user subject to that Authorization Database right can satisfy it without administrator authentication until the rule is restored or changed.
OPERATIONAL NOTE Because the backup is preserved after the first successful capture, later legitimate changes to Apple's or the organization's authorization rule are not reflected in the stored rollback copy.

The script does not install printer drivers, create queues, configure printer addresses, or determine which printers a user should add. Those functions remain separate from this authorization change.

Happy Scripting!

#!/bin/bash

# Allow Standard Users to Administer Printers
# Intended for deployment as root via NinjaOne.
#
# This changes ONLY the macOS authorization right:
#   system.preferences.printing
#
# Apple documents this right as allowing an account to add or remove printers.
# The original rule is backed up once for rollback.

RIGHT="system.preferences.printing"
BACKUP_DIR="/Library/Application Support/Agilant/AuthorizationDB Backups"
BACKUP_FILE="${BACKUP_DIR}/${RIGHT}.plist"

echo "=== Printer Authorization Configuration ==="

# Must run as root.
if [ "$(id -u)" -ne 0 ]; then
    echo "ERROR: This script must run as root."
    exit 1
fi

# Create protected backup directory.
if [ ! -d "$BACKUP_DIR" ]; then
    /bin/mkdir -p "$BACKUP_DIR" || {
        echo "ERROR: Could not create backup directory."
        exit 1
    }
    /bin/chmod 700 "$BACKUP_DIR"
fi

# Back up the original authorization rule only once.
if [ ! -s "$BACKUP_FILE" ]; then
    echo "Backing up existing authorization rule..."

    if ! /usr/bin/security authorizationdb read "$RIGHT" > "$BACKUP_FILE" 2>/dev/null; then
        echo "ERROR: Could not read $RIGHT from the Authorization Database."
        /bin/rm -f "$BACKUP_FILE"
        exit 1
    fi

    if ! /usr/bin/plutil -lint "$BACKUP_FILE" >/dev/null 2>&1; then
        echo "ERROR: Authorization rule backup was not a valid plist."
        /bin/rm -f "$BACKUP_FILE"
        exit 1
    fi

    /bin/chmod 600 "$BACKUP_FILE"
    echo "Original rule backed up to:"
    echo "$BACKUP_FILE"
else
    echo "Existing backup found; leaving it untouched."
fi

# Allow the authorization right without admin authentication.
echo "Allowing standard users to administer printers..."

if ! /usr/bin/security authorizationdb write "$RIGHT" allow >/dev/null 2>&1; then
    echo "ERROR: Failed to modify $RIGHT."
    exit 1
fi

# Verify the authorization rule now resolves to allow.
if /usr/bin/security authorizationdb read "$RIGHT" 2>/dev/null | /usr/bin/grep -q '<string>allow</string>'; then
    echo "SUCCESS: $RIGHT is now set to allow."
    echo "Standard users can perform printer add/remove operations governed by this right."
    exit 0
else
    echo "ERROR: The Authorization Database did not verify as expected."
    exit 1
fi
