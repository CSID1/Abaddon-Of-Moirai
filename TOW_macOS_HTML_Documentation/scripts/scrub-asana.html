Scrub Asana V1

The TOW Foundation · macOS · NinjaOne ShellScript

Explanation content is preserved from the current script explanation document. Raw-source tabs use the current available source files.

Script Purpose

Performs a destructive cleanup of existing Asana application files and selected per-user Asana data before a replacement deployment.

The script terminates Asana processes, removes the system-level application from /Applications/Asana.app, and iterates across local user home directories to remove selected Asana support files, caches, preferences, and saved application state.

This script is used as the cleanup half of the current Asana deployment workflow. The companion post-install script is Asana_Installation_Helper_V2.zsh, which relocates the freshly deployed application to /Users/Shared/Applications/Asana.app and assigns user ownership and write access.

How It Functions

Prints Uninstalling Asana... to the execution log before beginning cleanup.

Stops processes whose command line matches Asana case-insensitively by running pkill -if "Asana". Errors are discarded and ignored so the script continues even when no matching process is running.

Waits 2 seconds after process termination before deleting application data.

Deletes the system application path /Applications/Asana.app with rm -rf.

Enumerates every directory matching /Users/*. Non-directory entries are skipped; each directory is then treated as a potential user home for the cleanup operations that follow.

For each enumerated home directory, removes Library/Application Support/Asana beneath that directory.

Removes cache entries matching Library/Caches/*Asana*, preference files matching Library/Preferences/*asana*, and saved application-state entries matching Library/Saved Application State/*asana* for each enumerated user directory.

Also issues a removal command for Users/Shared/Applications/*asana* during each loop iteration. As written, this path is relative because it does not begin with /.

After the loop finishes, prints Asana uninstall complete. and exits with code 0.

Why This Script Is Deployed

The script is intended to eliminate remnants of an existing Asana deployment before the application is sent to the device again. This reduces the chance that a stale application bundle or previous user-level configuration interferes with the replacement install.

In the current workflow, the cleanup precedes the Asana installer and the companion Asana_Installation_Helper_V2.zsh step. That helper then moves the fresh application into the shared static path used by the environment and applies the ownership model required for user-driven Asana updates.

Dependencies And Deployment Notes
IMPORTANT CAVEAT This script deliberately deletes selected Asana data for every directory under /Users, not only the currently logged-in user. Removing Application Support, preferences, caches, and saved application state may reset local Asana state or require users to re-establish application preferences or session-related data after redeployment.
IMPORTANT CAVEAT The shared-application cleanup command currently uses Users/Shared/Applications/*asana* without the leading slash. It therefore resolves relative to the script's current working directory. It reliably targets /Users/Shared/Applications only when the working directory happens to make that relative path resolve there. The current script should not be treated as guaranteed to remove the shared Asana bundle.
IMPORTANT CAVEAT The script does not check the return status of individual rm operations and unconditionally prints Asana uninstall complete. followed by exit 0. A successful script exit therefore confirms that execution reached the end, not that every targeted item was actually removed.
OPERATIONAL NOTE The process match uses pkill -if "Asana", which is broader than matching only the primary Asana application process. Any running process whose command line contains the text Asana can be terminated by this step.
OPERATIONAL NOTE The script must execute with sufficient privileges to remove /Applications/Asana.app and data belonging to multiple local users. In a device-management workflow this normally means execution from a privileged management context.
RELATED SCRIPT After cleanup and reinstallation, Asana_Installation_Helper_V2.zsh is responsible for moving the application from /Applications/Asana.app to /Users/Shared/Applications/Asana.app and making the logged-in user the owner of the application bundle.

Happy Scripting!

Raw ZSH
Scrub_Asana_V1.zsh
ZSH
#!/bin/bash

echo "Uninstalling Asana..."

# Stop running Asana processes
pkill -if "Asana" 2>/dev/null || true

sleep 2

# Remove application
rm -rf "/Applications/Asana.app"

# Remove per-user Asana data
for USER_HOME in /Users/*; do
    [ -d "$USER_HOME" ] || continue

    rm -rf "$USER_HOME/Library/Application Support/Asana"
    rm -rf "$USER_HOME/Library/Caches/"*Asana*
    rm -rf "$USER_HOME/Library/Preferences/"*asana*
    rm -rf "$USER_HOME/Library/Saved Application State/"*asana*
    rm -rf "Users/Shared/Applications/"*asana*
done

echo "Asana uninstall complete."
exit 0
