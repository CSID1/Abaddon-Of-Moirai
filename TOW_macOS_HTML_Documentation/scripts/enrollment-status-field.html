macOS Enrollment Status Field

The TOW Foundation · macOS · NinjaOne ShellScript

Explanation content is preserved from the current script explanation document. Raw-source tabs use the current available source files.

Script Purpose

Evaluates whether a managed macOS device has completed the core enrollment workflow and writes the result into the NinjaOne custom field macosEnrollmentStatus. The field is set to either Enrollment Complete or Enrollment Incomplete.

Enrollment is considered complete only when all three required states are simultaneously confirmed: Setup Assistant has completed, the Mac is actively enrolled in MDM with NinjaOne configuration evidence present, and Platform SSO is registered and active for the currently logged-in user.

This script acts as the status bridge between local Mac enrollment state and the broader NinjaOne policy workflow. It does not itself deploy post-enrollment applications or configuration; it only determines and publishes the readiness state used by that workflow.

How It Functions

Defines the NinjaOne command-line utility path as /Applications/NinjaRMMAgent/programdata/ninjarmm-cli and targets the custom field key macosEnrollmentStatus.

Initializes three independent readiness flags - SETUP_COMPLETE, NINJA_MDM_READY, and PSSO_READY - to false. Each flag must later become true before the device can be marked complete.

Checks for /var/db/.AppleSetupDone. Presence of this file sets SETUP_COMPLETE=true, confirming that the normal macOS Setup Assistant completion marker exists.

Collects current MDM enrollment status with /usr/bin/profiles status -type enrollment and installed configuration-profile data with /usr/bin/profiles show -type configuration. Standard error is merged into the captured output for both commands.

Sets NINJA_MDM_READY=true only when the enrollment output contains MDM enrollment: Yes and the configuration-profile output contains at least one case-insensitive reference to NinjaOne, NinjaRMM, or ninjarmm.

Determines the current console user through /usr/bin/stat -f %Su /dev/console. An empty result, root, or loginwindow is treated as having no eligible signed-in user, leaving PSSO_READY=false.

For a valid console user, resolves the user UID with /usr/bin/id -u and executes /usr/bin/app-sso platform -s inside that user's GUI context using launchctl asuser and sudo -H -u.

Parses the Platform SSO status output and sets PSSO_READY=true only when all three conditions are present: "registrationCompleted": true, "state": "POUserStateNormal", and a supported login type of either POLoginTypePassword or POLoginTypeUserSecureEnclaveKey.

If SETUP_COMPLETE, NINJA_MDM_READY, and PSSO_READY are all true, assigns Enrollment Complete. Any other combination assigns Enrollment Incomplete.

Before writing the custom field, verifies that ninjarmm-cli exists and is executable. If it is unavailable, the script prints ERROR: NinjaOne CLI was not found. and exits with status 1.

Writes the selected value with ninjarmm-cli set macosEnrollmentStatus <value> and then prints the resulting custom-field value plus the three individual readiness flags for logging and troubleshooting.

Finishes with exit 0 after the write command and diagnostic output complete.

Current Workflow Integration

In the current Tow Foundation policy design, this script is associated with the scheduled automation 006 // MacOS Enrollment Status Field [Every 3min]. The scheduling is configured in NinjaOne; the script itself contains no timer or recurrence logic.

The resulting custom field is evaluated by the condition Enrollment Complete Automations, which checks whether MacOS Enrollment Status contains Enrollment Complete. When that condition becomes true, the post-enrollment automation set is allowed to run; when the field no longer meets the condition, the condition is configured to reset.

This makes the custom field a simple shared state indicator: local macOS readiness is evaluated on-device, while workflow execution remains controlled by the NinjaOne policy and condition layers.

Why This Script Is Deployed

The script prevents post-enrollment activity from being triggered merely because the Mac has appeared in MDM. It requires evidence that the user-facing setup process has finished and that the active user has a healthy Platform SSO registration before reporting the device as ready.

Supporting both POLoginTypePassword and POLoginTypeUserSecureEnclaveKey allows the same readiness check to work with either of the two Entra Platform SSO authentication modes used in this environment.

Publishing the result to a NinjaOne custom field also makes enrollment state visible to policy logic and technicians without requiring them to manually inspect Setup Assistant, MDM, and PSSO state on each Mac.

Dependencies And Deployment Notes
OPERATIONAL NOTE The script itself does not run every three minutes. That cadence belongs to the surrounding NinjaOne scheduled automation. Running this script manually performs only one immediate evaluation and field update.
IMPORTANT CAVEAT A valid interactive console user is required for PSSO_READY to become true. A Mac can therefore have completed Setup Assistant and be correctly enrolled in MDM yet still report Enrollment Incomplete while no eligible user is signed in.
IMPORTANT CAVEAT The MDM check proves two separate facts - active MDM enrollment and the presence of configuration-profile text matching NinjaOne|NinjaRMM|ninjarmm. It does not cryptographically prove that the active MDM enrollment server itself is NinjaOne. Stale or unrelated matching profile data could theoretically satisfy the second half of the check.
OPERATIONAL WARNING The PSSO check depends on the current text/JSON-like output produced by app-sso platform -s. If Apple changes field names or output formatting for registrationCompleted, loginType, or state, the regular-expression checks may stop matching and the device will remain Enrollment Incomplete until the script is updated.
OPERATIONAL NOTE The script intentionally accepts either Password-mode or Secure-Enclave-mode Platform SSO as complete, but requires the user state to be exactly POUserStateNormal. Other PSSO states are treated as incomplete rather than inferred to be healthy.
IMPORTANT CAVEAT The script verifies that ninjarmm-cli exists before attempting the custom-field write, but it does not check the exit status of the subsequent ninjarmm-cli set command. Because the script later ends with exit 0, a failed field write can still result in the overall script reporting success to the automation runner.

Failures from the profiles or app-sso status commands do not directly terminate the script. Their captured output simply fails the expected pattern checks, causing the applicable readiness flag to remain false and the published state to become Enrollment Incomplete.

The script is designed for execution from the NinjaOne management context where the NinjaOne agent and CLI are already present. It does not install the agent, create the custom field, create the surrounding condition, or define the scheduled automation that invokes it.

Happy Scripting!

Raw ZSH
MacOS_Enrollment_Status_Field.zsh
ZSH
#!/bin/bash

CLI="/Applications/NinjaRMMAgent/programdata/ninjarmm-cli"
FIELD="macosEnrollmentStatus"

COMPLETE_VALUE="Enrollment Complete"
INCOMPLETE_VALUE="Enrollment Incomplete"

SETUP_COMPLETE=false
NINJA_MDM_READY=false
PSSO_READY=false

# 1. Setup Assistant completed
if [[ -f "/var/db/.AppleSetupDone" ]]; then
    SETUP_COMPLETE=true
fi

# 2. Actively enrolled in MDM, with NinjaOne identifiable in the profiles
MDM_STATUS=$(/usr/bin/profiles status -type enrollment 2>&1)
PROFILE_DATA=$(/usr/bin/profiles show -type configuration 2>&1)

if printf '%s\n' "$MDM_STATUS" |
    /usr/bin/grep -Eiq 'MDM enrollment:[[:space:]]*Yes' &&
   printf '%s\n' "$PROFILE_DATA" |
    /usr/bin/grep -Eiq 'NinjaOne|NinjaRMM|ninjarmm'; then

    NINJA_MDM_READY=true
fi

# 3. PSSO registered and active for the currently logged-in user
CONSOLE_USER=$(/usr/bin/stat -f '%Su' /dev/console)

if [[ -n "$CONSOLE_USER" &&
      "$CONSOLE_USER" != "root" &&
      "$CONSOLE_USER" != "loginwindow" ]]; then

    CONSOLE_UID=$(/usr/bin/id -u "$CONSOLE_USER")

    PSSO_STATUS=$(
        /bin/launchctl asuser "$CONSOLE_UID" \
            /usr/bin/sudo -H -u "$CONSOLE_USER" \
            /usr/bin/app-sso platform -s 2>&1
    )

    if printf '%s\n' "$PSSO_STATUS" |
            /usr/bin/grep -Eq '"registrationCompleted"[[:space:]]*:[[:space:]]*true' &&
       printf '%s\n' "$PSSO_STATUS" |
            /usr/bin/grep -Eq '"loginType"[[:space:]]*:[[:space:]]*"POLoginType(Password|UserSecureEnclaveKey)' &&
       printf '%s\n' "$PSSO_STATUS" |
            /usr/bin/grep -Eq '"state"[[:space:]]*:[[:space:]]*"POUserStateNormal'; then

        PSSO_READY=true
    fi
fi

# Set the NinjaOne custom field
if [[ "$SETUP_COMPLETE" == true &&
      "$NINJA_MDM_READY" == true &&
      "$PSSO_READY" == true ]]; then

    VALUE="$COMPLETE_VALUE"
else
    VALUE="$INCOMPLETE_VALUE"
fi

if [[ ! -x "$CLI" ]]; then
    echo "ERROR: NinjaOne CLI was not found."
    exit 1
fi

"$CLI" set "$FIELD" "$VALUE"

echo "macosEnrollmentStatus: $VALUE"
echo "Setup Assistant complete: $SETUP_COMPLETE"
echo "NinjaOne MDM ready: $NINJA_MDM_READY"
echo "PSSO ready: $PSSO_READY"

exit 0
