TTF Wallpaper Installation Scripts

The TOW Foundation · macOS · NinjaOne ShellScript

Explanation content is preserved from the current script explanation document. Raw-source tabs use the current available source files.

Script Set Purpose

Provides three nearly identical macOS wallpaper-installation scripts used to apply Tow Foundation branded desktop backgrounds to the currently logged-in user.

All three scripts use the same execution logic. The only functional difference is the exact WALLPAPER_PATH value, which selects the dark, light, or medium wallpaper asset.

Script Variants

Install_Dark_Blue_TTF_Wallpaper.zsh -> /Users/Shared/Tow Foundation/TTF-Wallpaper-Dark-full.PNG

Install_White_Light_TTF_Wallpaper.zsh -> /Users/Shared/Tow Foundation/TTF-Wallpaper-Light-full.PNG

Install_White_Medium_TTF_Wallpaper.zsh -> /Users/Shared/Tow Foundation/TTF-Wallpaper-Medium-full.PNG

How It Functions

Runs under /bin/zsh and enables set -euo pipefail. The script therefore exits on an unhandled command failure, treats unset variables as errors, and propagates failures from commands executed in a pipeline.

Defines the selected branded image through the WALLPAPER_PATH variable. Each script points to one pre-staged PNG inside /Users/Shared/Tow Foundation.

Runs chmod 644 "$WALLPAPER_PATH" so the wallpaper file is readable by all local users while remaining writable only according to its ownership and the normal meaning of mode 644.

Checks whether the wallpaper exists with [[ ! -f "$WALLPAPER_PATH" ]]. If that branch is reached, the script prints Wallpaper file not found: ... and exits with status 1.

Determines the active console user with /usr/bin/stat -f%Su /dev/console and stores the result in CONSOLE_USER.

Treats an empty username, root, or loginwindow as no usable interactive session. In that state the script reports that the wallpaper file is present but no user session can be updated, then exits with status 0.

Resolves the logged-in user's numeric UID with /usr/bin/id -u "$CONSOLE_USER" and stores it in CONSOLE_UID.

Uses /bin/launchctl asuser together with /usr/bin/sudo -u so the subsequent AppleScript executes inside the logged-in user's session rather than merely in the script runner's context.

Passes the wallpaper path into /usr/bin/osascript and tells System Events to set the picture property for every desktop to the selected PNG.

Prints Wallpaper applied for <user>. after the AppleScript completes successfully.

Why These Scripts Are Deployed

These scripts provide a simple way to apply one of the approved Tow Foundation wallpaper variants after the corresponding image asset has already been placed on the Mac.

Keeping the three visual themes as separate scripts allows the deployment workflow to select a specific wallpaper without changing the underlying application logic. The dark, light, and medium scripts remain behaviorally consistent while differing only in the referenced image file.

Because the wallpaper change is executed in the active user's session, the script can update that user's desktop configuration even when the management action itself is launched from a different execution context.

Dependencies And Deployment Notes
OPERATIONAL WARNING The wallpaper image must already exist at the exact configured path before the script runs. These scripts do not download or create the PNG files.
IMPORTANT CAVEAT The script runs chmod 644 before it performs the explicit -f existence check. Because set -e is enabled, a completely missing wallpaper file causes chmod to fail and terminate the script immediately. In that case the later custom Wallpaper file not found branch will not execute.
OPERATIONAL NOTE If no usable console user is logged in, the script exits with status 0 after confirming the file is present. This means the run can be reported as successful even though no wallpaper was actually applied during that execution.
IMPORTANT CAVEAT Each run targets only the user represented by /dev/console at execution time. The scripts do not iterate through every local account or preconfigure wallpaper for users who are not currently signed in.

The AppleScript targets every desktop for the active user, so the selected image is applied across that user's currently represented desktop spaces/displays handled by System Events during execution.

If the shared storage path, image filename, branding asset, or deployment workflow changes, the corresponding WALLPAPER_PATH value must be updated in the affected script.

These three scripts are intentionally documented together because their control flow is identical. Their separate script files exist only to select different Tow Foundation wallpaper assets.

Happy Scripting!

Install Dark Blue TTF Wallpaper
Install_Dark_Blue_TTF_Wallpaper.zsh
ZSH
#!/bin/zsh
# Set the current logged-in user's desktop wallpaper.
# Store the image at the path below before running this script.

set -euo pipefail

WALLPAPER_PATH="/Users/Shared/Tow Foundation/TTF-Wallpaper-Dark-full.PNG"
chmod 644 "$WALLPAPER_PATH"

if [[ ! -f "$WALLPAPER_PATH" ]]; then
  echo "Wallpaper file not found: $WALLPAPER_PATH"
  exit 1
fi

CONSOLE_USER="$(/usr/bin/stat -f%Su /dev/console)"
if [[ -z "$CONSOLE_USER" || "$CONSOLE_USER" == "root" || "$CONSOLE_USER" == "loginwindow" ]]; then
  echo "No logged-in user. The wallpaper file is present, but there is no user session to update."
  exit 0
fi

CONSOLE_UID="$(/usr/bin/id -u "$CONSOLE_USER")"

/bin/launchctl asuser "$CONSOLE_UID" \
  /usr/bin/sudo -u "$CONSOLE_USER" \
  /usr/bin/osascript - "$WALLPAPER_PATH" <<'APPLESCRIPT'
on run argv
    set wallpaperPath to item 1 of argv
    tell application "System Events"
        tell every desktop
            set picture to (POSIX file wallpaperPath)
        end tell
    end tell
end run
APPLESCRIPT

echo "Wallpaper applied for $CONSOLE_USER."
