Overview

Description

This configuration manages NinjaOne agent-based third-party software patch scanning, approval, installation, user-notification behavior, application-close behavior, and reboot handling. This is once again disabled for Pre-Enrollment for the same reasons that OS patching is disabled for Pre-Enrollment.

Software Patching is used to maintain supported third-party applications independently from macOS operating-system patching.

The Software Patching update schedule is intentionally configured on different days from the OS Patching update schedule so that third-party application maintenance and operating-system maintenance are not scheduled to execute on the same day.

The exact enabled/disabled state of Software Patching may vary between

000 Master MacOS Policy

001 Pre-Enrollment Policy

002 Post-Enrollment Policy

However, the software catalog included within Software Patching remains consistent across all three policies.

Applications installed and managed through Apple Apps and Books / VPP are configured to be excluded from NinjaOne Software Patching. This prevents NinjaOne agent-based patching from independently updating applications whose installation/update lifecycle is being managed through VPP.

Applications whose installation is managed through Apple Apps and Books / VPP are excluded from NinjaOne's agent-based Software Patching workflow.

This prevents two separate management systems from attempting to independently control the update lifecycle of the same managed application.

An application may still appear in the Software Patching software catalog documented later in this section. Its presence in the supported software list does not mean that a VPP-installed instance of that application will be patched through NinjaOne.

000 Master Policy Effective Software Patching Behavior

Software Patching is enabled.

VPP / Apps and Books-managed application installations are excluded from NinjaOne Software Patching.

Software patch scans occur:

Monday

Wednesday

Friday

Scans begin at 08:30 AM local device time and are staggered across 2 hours and 30 minutes.

Missed scans execute as soon as possible afterward.

Detected patches are not configured to install immediately during the scan.

Approved third-party application updates occur:

Tuesday

Thursday

Saturday

Updates begin at 08:30 AM local device time and are staggered across 2 hours.

These Software Patching update days do not overlap with the configured OS Patching update days.

Missed update windows do not trigger immediate installation through the "Run update immediately, if missed" option.

Maintenance mode suppresses:

- Email/SMS/Push notifications

- Condition alerts

- Notification channels

If an update requires currently running software to close:

- The user is prompted before the application is closed.

- The prompt repeats every 15 minutes.

- NinjaOne is configured for 6 prompts.

- The final prompt remains for 5 minutes.

- The application is then forcibly closed and the patch proceeds.

If an application patch requires a restart while a user is logged in:

- The user is prompted to restart.

- Restart prompts repeat every 25 minutes.

- NinjaOne is configured for 6 prompts.

- The final prompt remains for 5 minutes.

- The Mac is then forcibly restarted if required.

If no user is logged in and the patch requires a restart:

- The Mac reboots immediately.

Critical patches are approved.

Recommended patches are approved.

No individual patch approval or rejection overrides are currently configured.

Nine third-party software products are included within the Software Patching catalog.
