Overview

Description

Scheduled Automations define groups of NinjaOne automation items that execute according to a specified device or user event, recurring interval, or one-time execution schedule.

Each Scheduled Automation acts as a parent container for one or more individual automation items. These child automation items may include:

  • Application installations
  • File transfers
  • macOS shell scripts
  • Device configuration actions
  • User environment configuration
  • Resource deployment
  • Other NinjaOne-supported automation types

Scheduled Automation groups 001 through 008 are configured at the 000 Master MacOS Policy level. Individual Scheduled Automation groups may be enabled or disabled differently within the 001 Pre-Enrollment Policy and 002 Post-Enrollment Policy.

The effective status of each Scheduled Automation is therefore documented independently below.

Each child automation will be documented in greater detail later. Depending on the automation type, supporting documentation may include:

  • Raw script file
  • Transferred resource/file
  • Application/package information
  • Detailed explanation document
  • Dependencies
  • Execution logic
  • Expected behavior/result

The information in this section primarily documents

  1. Which Scheduled Automation groups exist
  2. Their execution schedule
  3. Whether each group is active within each policy
  4. Which child automations are contained within each group
  5. The order in which those child automations are configured

General Behavior

Child automations are executed according to the schedule configured on their parent Scheduled Automation.

The ordering documented below reflects the configured automation order within NinjaOne.

Disabling a Scheduled Automation prevents its configured automation sequence from being invoked by that Scheduled Automation, while the individual automation objects themselves may continue to exist within NinjaOne.

Individual scripts, applications, and file-transfer actions may also be reused by Conditions or other Scheduled Automations elsewhere in the policy architecture.

006 // Macos Enrollment Status Field [Every 3Min]
000 Master Status
Enabled
001 Pre-Enrollment Status
Enabled
002 Post-Enrollment Status
Disabled
Description
Pre-Enrollment Only; This designed to function right as enrollment is finishing up, in an effort to act as the "logic" behind makeshift dynamic policy assignments. Essentially, this scripts evaluates if the device has met three specific conditions, and upon doing so, it writes a new value to the devices inventory record in NinjaOne for the Enrollment Status custom field, indicating that enrollment is complete. When this happens, eventually, another script or logic instance will move the device into the post-enrollment location, and as a result, change the assigned policy as well.

Executes every three minutes while this Scheduled Automation remains active.

This workflow manages the custom "MacOS Enrollment Status" field referenced by the Enrollment Complete condition documented in S.II / T.I.

The internal logic of the script and the possible custom-field values will be documented separately in the detailed automation documentation.

Configured Automation Order

  1. MacOS Enrollment Status Field
Type
ShellScript (Mac)

Evaluates enrollment-related device state and updates the "MacOS Enrollment Status" NinjaOne custom field accordingly.

The resulting custom-field value is used by other policy logic, including the "Enrollment Complete Automations" condition.
