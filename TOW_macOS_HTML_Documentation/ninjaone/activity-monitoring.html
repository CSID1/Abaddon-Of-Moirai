Overview

Description

Activity Monitoring controls which NinjaOne-generated device, security, application, backup, operating-system, and integration events generate technician notifications and which notification channels receive those events.

The Activity Monitoring configuration is identical across

000 Master MacOS Policy

001 Pre-Enrollment Policy

002 Post-Enrollment Policy

Most events configured to notify technicians are routed through the Microsoft Teams notification channel named:

Technicians (Teams)

Certain higher-priority events are additionally routed through

TOW Technicians (Teams)

Events configured with "Notify Technicians: No" do not generate a technician notification through this policy configuration.

This section documents the event-monitoring and notification-routing configuration only. It does not modify the configuration of the underlying integrations or services that generate these events.

Policy Behavior Summary

Activity Monitoring is configured identically across all three macOS policies.

Activity Monitoring does not itself define the underlying antivirus, backup, software, or operating-system behavior. It determines which events generated by NinjaOne or its integrations are surfaced to technicians.

Events marked "Notify Technicians: Yes" generally route alerts to:

Technicians (Teams)

Certain events additionally route to:

TOW Technicians (Teams)

Events observed with the additional TOW Technicians notification channel include:

- CrowdStrike Mitigation Failed

- CrowdStrike Quarantine Failed

- CrowdStrike Remediation Failed

- GravityZone Threat Ignored

Routine success/start/completion events are frequently configured without notifications, while failure, threat, security-state, hardware-change, and other notable events are generally configured to notify technicians.

CrowdStrike and SentinelOne activity rules remain configured within Activity Monitoring even though Bitdefender GravityZone is the antivirus integration currently selected for this macOS policy.

Those monitoring entries do not deploy CrowdStrike or SentinelOne themselves; they define notification behavior if NinjaOne receives the corresponding activity event.

Configuration Ownership: This documentation describes the current implementation and does not constitute authorization to modify it. Configuration changes should be coordinated with the endpoint-management owner and reflected in the corresponding source configuration.
